# Learning roadmap

## Purpose

Engineering Mastery Lab has two linked learning tracks:

- the complete E0-E4 prerequisite roadmap for durable engineering capability;
- the accelerated S001-S110 reboot for bounded daily execution and evidence.

Neither track is an accreditation decision, competency assessment,
qualification, professional licence, or substitute for independent
engineering verification.

## Complete capability stages

| Stage | Purpose | Domain modules |
|---|---|---:|
| E0 Engineering Starter | Rebuild learning practice, SI discipline, algebra, vectors and coordinate frames | 3 |
| E1 Undergraduate Foundations | Re-establish mathematics, physics, reproducible computing, programming and engineering graphics | 5 |
| E2 Mechatronics Core | Integrate mechanics, manufacturing, circuits, sensing, embedded systems, communication, signals and control | 8 |
| E3 Robotics and AI Specialisation | Build robot dynamics, ROS 2, state estimation, navigation, perception and evaluated AI/ML | 7 |
| E4 R&D Mastery and Proof | Integrate systems engineering, safety, verification, communication and capstone proof | 2 |

The roadmap is a prerequisite graph, not a flat checklist. Every module shows
its incoming dependencies and remains reachable from an entry module.
Progress records exposure, practice, evidence and mastery independently.

Each module uses the same substantive learning-object contract:

1. Plain-language explanation and measurable outcomes.
2. Prerequisites, vocabulary and symbols.
3. Equations with SI units and dimensional checks.
4. A worked numeric example with an independent recomputation.
5. Retrieval practice and one practical build or test.
6. Common mistakes and diagnostic guidance.
7. Evidence requirements and a mastery gate.
8. Source provenance and an accessible text equivalent.
9. An optional design-review question where useful.
10. Non-accrediting educational mapping to Engineers Australia Stage 1
    categories.

## Accelerated reboot

The authoritative workbook defines 110 sessions, S001-S110, totalling 2,750
minutes. That is exactly 45 hours 50 minutes. The sessions are organised as:

| Milestone | Sessions | Blocks | Outcome |
|---|---|---:|---|
| M0 Reset and diagnostic | S001-S006 | 6 | A measurable system boundary and baseline |
| M1 Computing foundations | S007-S016 | 10 | Reproducible Python and Git workflow |
| M2 C++ and robot maths | S017-S028 | 12 | Tested differential-drive and frame calculations |
| M3 ROS 2 core | S029-S040 | 12 | Inspectable ROS 2 package and sensor-log workflow |
| M4 Robot model, simulation and control | S041-S052 | 12 | Teleoperated simulated rover with valid geometry and control |
| M5 Localisation, SLAM and Nav2 | S053-S066 | 14 | Repeatable autonomous simulated mission |
| M6 Embedded, electronics and motor control | S067-S078 | 12 | Timed embedded motor boundary with fault evidence |
| M7 Perception and applied AI/ML | S079-S090 | 12 | Measured perception mission with failure analysis |
| M8 Integration, testing and reliability | S091-S100 | 10 | Requirements-to-test traceability and injected-fault regression |
| M9 Capstone release and interview proof | S101-S110 | 10 | Reproducible portfolio release and defensible demonstration |

Every ordinary session is structured as a micro-lesson, build or test,
retrieval close, evidence requirement, source slice and local attempt record.
A ten-minute stuck rule records the exact blocker and the smallest useful next
test without falsely completing the session.

## Diagnostic and proof rules

Each milestone has one practical diagnostic scored from 0 to 4.

- 0 to 2 means study required.
- 3 or 4 may skip ordinary lesson sessions in that milestone.
- Diagnostic skipping never proves mastery.
- Every milestone proof and release session remains mandatory.
- Completion state, blocker, confidence, evidence and mastery-gate result
  remain separate.

|---|---|---|---|
| P1 | S001-S040 | Inspectable rover software foundations | Reproducible workspace, ROS graph and sensor evidence |

| P4 | S067-S110 | Perception-enabled inspection rover | Embedded motor control, measured perception, safe actuation, diagnostics and complete release |

Hardware purchases are optional and remain outside the product. Buy only for a
documented evidence gap that simulation cannot resolve.

## Daily and weekly use

Today presents one dominant Continue action, current capability stage, current
milestone, current rover release, evidence completed in the local week and a
minimum viable day.

The weekly review uses the workbook's twelve-week planned-block template and a
separate ISO calendar-week key. Record completed blocks, retained evidence and
a short reflection. Missing private calendar events are treated as unknown,
not as free time. The implementation contains no copied personal Calendar Fit
values.

## Portfolio end state

The capstone is ready only when material claims trace through need,
requirement, decision, test, result and retained evidence. An independent
reviewer must be able to reproduce a key result and identify limitations
without relying on unsupported narrative.
